# UI 작업 규칙 (항상 적용)

웹페이지·랜딩·미니앱 화면을 만들거나 고칠 때, 코드 한 줄 쓰기 전에 아래를 먼저 한다.

## 1. 스타일부터 확정한다

"예쁘게"는 스타일이 아니다. 아래 10개 중 **하나**를 골라 이름을 말하고 시작한다.
업종에 맞는 걸 고른다. 예쁜 걸 고르는 게 아니다.

**신뢰·전문** (변호사·세무사·컨설팅·B2B·고가서비스)
- 미니멀리즘 — 여백 넓게, 요소 덜어냄 · stripe.com
- 에디토리얼 — 세리프 + 큰 사진, 잡지 지면 · kinfolk.com (웨딩·브랜드스토리·출판)
- 벤토 그리드 — 카드 칸 배치, 정보 많을 때 · apple.com (SaaS·기능많은 서비스)

**세련·트렌디** (테크·앱·스타트업)
- 글래스모피즘 — 반투명 유리, 어두운 배경 위 깊이감 · authkit.com
- 그라디언트 메시 — 오로라 배경, 사진 없이 화면 채움 · partiful.com
- 다크모드 — 어두운 배경 + 포인트 컬러 하나 · vercel.com (개발·크리에이티브·바/나이트)
- 뉴모피즘 — 볼록 버튼, 대비 낮음. 버튼·카드에만 부분 적용 · 웰니스·헬스케어

**개성·임팩트** (타깃 명확할 때만)
- 브루탈리즘 — 큰 타이포, 강한 대비, 날것 · flowen.me (패션·아트·음악)
- 레트로/Y2K — 픽셀, 형광 · poolsuite.net (2030·F&B·굿즈)
- 3D 인터랙티브 — 스크롤 반응. 로딩 무거우면 이탈 · bruno-simon.com

스타일 두 개 이상 섞지 않는다. 정리 안 된 인상만 준다.

## 2. 수치는 감으로 정하지 않는다

`~/.claude/design-refs/web-craft-baseline.md`를 읽는다. 실측값이다. 최소한 이것들:

- 배경에 **순백(#FFF)·순검정(#000) 금지** — 라이트 #F2~#F7, 다크 #08~#1F
- 본문은 14~15px 계열 (측정한 9곳 전부 16px 미만)
- radius는 **계열 하나만** — 타이트 2~8px / 소프트 14~32px / pill 중 택1
- transition 160ms ease-out, 큰 모션은 480ms `cubic-bezier(.16,1,.3,1)`
- letter-spacing 본문 0~-0.02em, 디스플레이 -0.02~-0.04em

## 4. 끝났다고 말하기 전에

폰 폭(320·390·430)에서 스크린샷 찍어 직접 본다. 안 봤으면 "완료"라고 하지 않는다.
가독성이 효과보다 위다. 효과가 글씨를 방해하면 효과를 뺀다.

AI 티 체크 (`~/.claude/design-refs/korean-agency-baseline.md` 12개 중 핵심):
- 히어로 제목은 고객의 질문·고민 한 문장. 은유 금지.
- 영문 모노 대문자 라벨·섹션 번호(Nº 0X)·가는 선 표 금지. 목록·가격도 카드로.
- 브랜드색 1개를 면적 10~40%로 쓰는 블록 최소 2곳.
- 한글 제목 700~800 · 자간 -0.01~-0.02em · 줄간 1.15~1.25.
- 이펙트는 대표 하나 + 작은 장난 하나. 나머지는 정적.
